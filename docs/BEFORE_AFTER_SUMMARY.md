# Before / After Summary

## Before

- Homepage functioned as a field operations manual  
- Primary nav mixed voters with Pulsar, field tools, roadmap  
- Large multi-paragraph development notice dominated every page  
- Horizontal mobile nav; no hamburger  
- Red-default CTAs; dense card stacks  
- Candidate page: long unfiltered lists  
- Volunteer form: very long first step; some options pre-checked  
- TBA / planned events could appear as featured or calendar-ready  

## After

- Homepage structured for CRO journeys A–C (ballot, volunteer, events)  
- Public IA: Home · Ballot · Candidates · Events · Volunteer · District Facts · More  
- Slim development banner with expandable details  
- Desktop nav + accessible mobile drawer + mobile sticky actions  
- Civic design system (navy / river / evergreen / cream; restrained accent)  
- Filterable candidate directory; supported local labels  
- Volunteer quick-start + optional full form; no pre-checked marketing packs  
- Events default to **confirmed**; proposed/past separated; ICS only when confirmed  
- Ops tools under `/portal`  
- New trust pages: District Facts, About, Sources, Corrections  
- Privacy-conscious analytics stub (disabled)  
- Smoke tests via `npm test`  

## Preserved

- All JSON data files  
- Ballot lookup, map, events data, field routes  
- POST block in development for collection endpoints  
- SOS source links and legal pages  
- Session + Render deploy configuration  
- Secondary routes (not deleted)  

## Not done (owner)

- Deploy (explicitly out of scope for this pass)  
- Password-secured captain auth  
- Real analytics instrumentation / third-party tools  
- Production SEO enablement  
- Cited election-result datasets on District Facts  
- Licensed candidate photography
